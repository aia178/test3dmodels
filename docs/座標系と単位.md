# 座標系と単位

座標・軸・左右の取り違えは、GPU を強くしても直りません。ここに決めたことを書き、テストで確かめています。

## 単位

- 内部はすべて **メートル [m]**。
- 画面の入力・表示だけ cm。変換は `web/src/core/units.ts` の `parseCm` / `fmtCm` / `fmtCmExact` を通す。
- 推定値は cm の整数で表示する（小数点以下を精度の証拠に見せない）。人が入力した値は 0.1cm まで表示する。
- 角度は内部ラジアン。扉の最大開き角 `maxAngleDeg` と画面の「向き」だけ度。

## 部屋座標（room）

- 右手系、**Y が上**、床が **y = 0**。
- 平面図は (x, z)。画面では x が右、z が下（3D を真上から見た向きと同じ）。
- 輪郭 `outline` は (x, z) を普通の 2D 平面とみたとき**反時計回り**（符号付き面積が正）。
- 辺 i は `outline[i] → outline[i+1]`。室内は進行方向の**左**。室内向きの法線は `(-d.z, d.x)`。
- 設備 `Fixture` は「辺の番号」と「始点から中心までの距離 `offset`」で壁の上の位置を表す。

## 家具

- ローカル座標: 幅 = x、奥行き = z、高さ = y。**正面は +z**。
- `rotY` は Three.js の `rotation.y` と同じ向き（+90° で +x が −z を向く）。`geom.ts` の `rotY` と一致することをテストしている。
- 位置 (x, z) は底面の中心。`elevation` は床から底面まで。

## 復元モデルの座標（world）→ room

- MapAnything の出力: 点は world 座標、カメラ姿勢は **OpenCV 規約（+X 右、+Y 下、+Z 前）の cam2world** 行列。
- 上方向の初期値: 各カメラの画像の上（= カメラの −Y 軸）の平均。その後、床の平面を当てて法線で置き換える。
- world → room は `T_room_from_world`（4×4、列ベクトルに左から掛ける）。回転 R と平行移動だけで、`det(R) = +1` を実行時に確認している（鏡映を入れない）。
- 床平面内の回転（yaw）は、壁の点の分布が最も鋭くなる角度で決める。
- 行列の適用は numpy の行ベクトル表記で `p_room = p_world @ R.T + t`。

## 縮尺

- 点群（`cloud.bin`）は**縮尺補正前**の room 座標で保存する。表示のときに `room.scale.factor` を掛ける。
- 輪郭・障害物・設備の位置・測定点は、縮尺合わせのたびに同じ比率で書き換える（`room.ts` の `applyScale`）。
- 人が入力した大きさ（設備の幅・高さ、手入力の天井高、手で作った障害物の寸法）は実寸なので変えない。
- 形や縮尺が変わるたびに `geometryVersion` を上げる。判定結果は、計算に使った版を持つ。

## テストで確かめていること

- `judge.test.ts`「単位と座標」: cm↔m、回転の向き、正面の向き、左右。
- `room.test.ts`: 時計回りの輪郭を受け付けない、縮尺合わせで何が変わり何が変わらないか。
- `server/tests/test_structure.py`: 任意に回転・傾けた world から、柱が**鏡に映らない向き**で復元されること。
