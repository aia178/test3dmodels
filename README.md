# RoomFit

部屋を写真から立体にし、手持ちの家具や買いたい家具を置いて、「置けるか・使えるか・確認が必要か」を理由つきで示すアプリです。

> **現在の到達点（2026-10-12）**: 第1段階（中核の実現性確認）の途中です。
> 写真 → 復元 → 形の確認 → 縮尺合わせ → 家具配置 → 判定 → 保存、の一連の経路は Web 版で動きます。
> ただし **実測つきの実際の部屋での精度評価はまだ行っていません**（手元に実測データが無いため）。
> 「できていること／できていないこと」を下に分けて書いています。完成品ではありません。
>
> 実機・実データで測った数字と、そこから決めた方針は [docs/検証記録.md](docs/検証記録.md) にまとめています。

## 2. セットアップと起動（Windows）

必要なもの: **Node.js 22 以上**、**uv**（Python の管理ツール。Python 3.12 は uv が用意します）、ディスク空き 約 10GB（PyTorch と重み 4.6GB）。Mac・GPU は不要です。

```bat
start.cmd
```

初回は依存関係の取得と Web のビルドを行い、`http://127.0.0.1:8787` で起動します。エクスプローラーで `start.cmd` をダブルクリックして起動します（実行して確認済み。このファイルは、文字化けを避けるため英数字だけで書いています）。最初に写真からの復元を実行したとき、重み（`facebook/map-anything-apache`、約 4.6GB）が Hugging Face から自動でダウンロードされます。

手動で行う場合:

```bat
npm --prefix web ci
npm --prefix web run build
uv run --directory server uvicorn roomfit.app:app --host 127.0.0.1 --port 8787
```

開発時（画面を書き換えながら確認）は、サーバーを上のコマンドで起動したうえで、別の画面で `npm --prefix web run dev` を実行し `http://127.0.0.1:5173` を開きます。

依存関係は `web/package-lock.json` と `server/uv.lock` で固定しています。

### 商品検索（任意）

楽天ウェブサービスでアプリ ID を取得し、環境変数 `RAKUTEN_APP_ID`（任意で `RAKUTEN_AFFILIATE_ID`）を設定してからサーバーを起動すると、「商品を検索して登録」が使えます。設定例は [.env.example](.env.example)。ID はサーバーだけが持ち、画面側へは渡しません。未設定のときは画面に「未設定」と表示され、URL と寸法の手入力での登録になります。取得できるのは商品名・価格・店名・リンク・説明文で、**寸法は自動では決めません**（説明文から寸法らしい記載を候補として見せ、利用者が本体の外寸を入力します）。

### スマホから使う（同じ Wi-Fi）

`start.cmd` の `--host 127.0.0.1` を `--host 0.0.0.0` に変えて起動し、スマホのブラウザで `http://<PCのIPアドレス>:8787` を開きます。iPhone でも、写真の登録・結果の閲覧・家具配置・比較が使えます。

- 同じ Wi-Fi にいる人がこのサーバーへ届くようになります。学校など共用のネットワークでは使わないでください（写真は端末ごとのトークンで守られますが、通信は暗号化されていません）。
- データは開いたブラウザごとに保存されます。PC とスマホで自動的には共有されません（設定 → バックアップで移せます）。

### Android 撮影アプリ（任意）

`android/` を Android Studio で開くか、JDK 17 以上（確認は 21）を `JAVA_HOME` に設定して次を実行します。`android/local.properties` に `sdk.dir=<Android SDK の場所>` が必要です（Android Studio で開くと自動で作られます）。

```bat
cd android
gradlew.bat assembleDebug
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

- 端末に「Google Play Services for AR（ARCore）」が必要です。無い・非対応の場合は、アプリが理由を表示します。
- 「記録を始める」を押し、**ゆっくり**向きを変えると場面が自動で保存されます（15cm 動くか 12° 回るごと。速すぎる場面は保存しません。最大 60 枚）。
- 実機で分かったこと（OnePlus 13）: この端末は深度センサーを使わず、動きから深度を推定します。速く動かすと位置が 1m 以上飛ぶ場面や、深度が空の場面が出ました。
- 記録は端末の `Android/data/jp.roomfit.capture/files/captures/<日時>/` に保存されます。PC への取り出しと処理:

```bat
adb exec-out "cd /sdcard/Android/data/jp.roomfit.capture/files/captures/<日時> && tar -cf - ." > capture.tar
uv run --directory server python ../experiments/run_arcore.py <展開したフォルダ> <出力フォルダ>
```

（`adb pull` でフォルダごと取り出すと途中で止まることがあったため、tar でまとめています。）

## 4. 設計の要点

### 処理の置き場所

| 処理 | 場所 | 理由 |
|---|---|---|
| 写真の登録、明るさ・ぼけの簡易チェック | ブラウザ | 送信前に分かることは端末で知らせる |
| 写真 → 点群・カメラ姿勢（MapAnything） | サーバー（この PC の CPU） | メモリ 5GB 超・数分かかるためジョブとして実行 |
| 点群 → 床・壁の輪郭・未確認の辺 | サーバー | 元の点群が必要 |
| 配置・判定・保存 | ブラウザ（IndexedDB） | 家具を動かすたびに重い処理を呼ばない。通信が切れても編集を続けられる |

### 座標と単位

- 内部単位はメートル。cm は画面との境界でだけ変換します（`web/src/core/units.ts`）。
- 部屋座標は右手系・Y が上・床が y=0。平面図は (x, z)。輪郭は (x,z) で反時計回り。
- 復元モデルの座標（OpenCV 規約の cam2world）→ 部屋座標は回転と平行移動だけで、鏡映を入れません。
- 詳細: [docs/座標系と単位.md](docs/座標系と単位.md)

### 判定の考え方

- 状態は 3 つ: **問題あり**（根拠のある干渉・不足）/ **要確認**（誤差・欠損・未入力で判断できない）/ 問題を検出せず。総合点は出しません。
- 見込む誤差は、復元モデルの「信頼度」からは作りません。**縮尺合わせに使っていない場所の実測との差の最大値**を使います。検証が無いうちは仮の値（5cm、縮尺未確認なら 10cm）で、その旨を表示します。
- 誤差を見込むと結果が逆転し得る隙間・重なりは「要確認」にします。
- 撮れていない壁（未確認）へのはみ出しは、問題なしにも問題ありにもせず「要確認」にします。
- 寸法が未確認の家具が関わる判定は、断定せず「要確認」にします。
- 通路は、入口の扉から各家具の正面までの**連続した経路**で、いちばん狭い所の幅を求めます（最短距離の計測ではありません）。入口が未登録なら「判定していません」と表示します。
- 通路幅の初期値 60cm は目安として置いた値で、法令・安全の基準ではありません（画面にも明記）。

### 既知の割り切り

- 家具は直方体。脚の下の空きは「分かれば入力」で、コンセントが脚の下に収まるかだけに使います。
- 背の高い家具やカーテンが、復元では「壁」や「縦の構造物」として出ることがあります。自動で出たものは「未確認」とし、人が確認・修正します。
- 縮尺合わせは全体の大きさだけを直します。ゆがみは直りません。

## 6. データの保存・削除・バックアップ

| データ | 場所 | 削除 |
|---|---|---|
| 部屋の形・家具・配置案・設定 | ブラウザの IndexedDB（`roomfit`） | 各画面の削除ボタン、または 設定 → すべてのデータを削除 |
| 送信前の写真、復元した点群 | 同上 | 部屋の削除で消えます |
| アップロードした写真・復元結果・ジョブ記録 | `server/data/`（`jobs/<id>/` と `roomfit.sqlite3`） | 部屋の削除・「すべてのデータを削除」でサーバー側も消します。手動なら `server/data` フォルダを削除 |

- バックアップ: 設定 → 「バックアップを保存」で JSON を書き出し、「バックアップから読み込む」で戻します。写真と点群は含みません。
- サーバーを再起動すると、実行中だった復元は「中断」と記録され、画面から同じ写真でやり直せます。

## 7. 精度を評価するために必要なデータ（お願い）

実際の部屋での精度はまだ分かっていません。次のデータがあれば評価できます。

1. **部屋**: できれば柱か壁の出っ張りがある部屋を 1 つ。物が少ないほど評価しやすいです。
2. **写真**: 部屋の中央付近から、少しずつ向きを変えて一周（12〜20 枚、隣と半分ほど重なるように）。床と壁の境目を毎回入れる。柱・出っ張り・コンセントは、1.5m ほど離れた位置から 2〜3 枚追加。スマホの向きは揃える。
3. **実測（メジャー）**: 次の 7 か所以上を cm 単位（できれば mm まで）で。
   - 壁の幅を 2 面（長い区間）
   - 天井高
   - 柱・出っ張りの幅と奥行き（短い区間）
   - 扉の幅、窓の幅
   - コンセントの床からの高さと、近い角からの距離
4. アプリで 1 か所を縮尺合わせに使い、残りを「検証」として記録すると、差の平均・最大が「部屋の確認 → ② 縮尺と精度」に表になります。

目標値の案（測定対象別）: 壁の幅など 1m 以上の区間は差 3cm 以内、柱の出っ張りなど 1m 未満の区間は差 1cm 以内。**現状この目標を満たせるかは未確認**で、満たせない場合は撮影方法の見直し・ARCore の深度の併用・別方式（COLMAP、VGGT）との比較に進みます。

## 8. デモ手順

### 実データ（公開サンプルの室内実写真）での流れ

1. `start.cmd` で起動し、ホームの「内見した部屋を登録」→「撮影済みの写真から作成」。
2. 写真を 8 枚以上選び、送り先の説明に同意して「立体にする」。段階が表示され、数分で完了します。
3. 「部屋の確認」で、灰色の点（復元結果）と壁の線を見比べ、壁を確認済みにする／動かす。
4. 「② 縮尺と精度」で 2 点を選び実測値を入れて縮尺を合わせ、別の場所を検証として記録する。
5. 「③ 設備」で扉（入口）とコンセントを壁に置く。
6. 家具を登録し、配置案を作って家具を置く。確認結果の一覧から問題を選ぶと場所が強調され、「提案の分だけ動かす」で直して再判定されます。

公開サンプル（VGGT リポジトリの `examples/room`）は**実測値が無い**ため、精度の説明には使えません。処理が実写真で動くことの確認用です。

### 用意しておいた部屋（部屋ファイル）で見せる

復元には数分かかるので、発表ではあらかじめ作った部屋を使うのが安全です。

1. `start.cmd` で起動し、ブラウザで `http://127.0.0.1:8787` を開く。
2. ホームの「部屋ファイルを読み込む」で `demo/home_corner.roomfit.json` を選ぶ（自宅の角を写真 13 枚から復元したもの。元の写真は入っていません）。
3. 「3D で見る」を押し、ドラッグで回す。
4. 「新しい配置案を作る」→ 家具を置く →「3D」→「写真から復元した点」にチェック。
5. 「確認結果」で、要確認の理由を見せる。

部屋ファイルは、部屋の画面の「部屋ファイルに書き出す」で作れます（別のブラウザや端末へ移すときにも使えます）。実験で復元した結果からは `experiments/make_room_file.py` で作ります。

### 寸法入力の部屋（合成・補助経路）での流れ

「寸法を入力して作成」で 400×300×240cm の部屋を作り、5〜6 と同じ操作を行います。これは復元を通らない補助経路で、**写真からの復元のデモではありません**。
